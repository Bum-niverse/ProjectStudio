# ProjectStudio MVP 아키텍처 v0.1

## 결정 요약

ProjectStudio는 로컬 우선 단일 사용자 데스크톱 앱으로 시작한다. UI는 React와 TypeScript, 데스크톱 셸과 운영체제 접근은 Tauri, 영속 저장소는 SQLite를 사용한다. UI가 Tauri 명령이나 Git CLI를 직접 호출하지 않도록 응용 서비스와 어댑터 경계를 둔다.

초기 MVP는 문서 모델과 추적 가능성을 먼저 안정화한다. 유저플로우와 와이어프레임은 같은 문서·리비전 모델 위에 후속 문서 유형으로 추가한다.

## 계층과 책임

```text
React UI
  -> application use cases
    -> domain model and repository ports
      -> SQLite / file system / Git / AI adapters
        -> Tauri commands and operating system
```

- `ui`: 화면, 폼 상태, 로딩·빈 상태·오류·복구 안내를 담당한다.
- `application`: 프로젝트 생성, PRD 초안 생성, 문서 저장, 변경안 승인·거절 같은 유스케이스를 조합한다.
- `domain`: 프로젝트, 문서, 리비전, 기능, 추적 링크와 변경안의 규칙을 외부 기술과 무관하게 표현한다.
- `ports`: 저장소, AI 공급자, Git, 파일 내보내기 인터페이스를 정의한다.
- `adapters`: SQLite, 개발 모드 PRD 생성기, Git CLI와 파일 시스템 구현을 격리한다.
- `tauri`: 허용된 로컬 기능만 명령으로 노출하고 입력 경로와 Git 인자를 검증한다.

## 권장 저장소 구조

```text
src/
  ui/
  application/
  domain/
  ports/
  adapters/
src-tauri/
  src/
  migrations/
tests/
docs/
```

실제 Tauri 프로젝트 초기화 시 생성 도구의 기본 구조와 충돌하지 않는 범위에서 이 경계를 적용한다.

## 핵심 데이터 모델

| 개체 | 목적 | 주요 관계 |
| --- | --- | --- |
| `projects` | 로컬 프로젝트와 선택적 Git 저장소 | 여러 문서·기능·개발 작업 보유 |
| `documents` | PRD, 기능명세, 유저플로우, 와이어프레임의 논리적 문서 | 현재 리비전을 가리킴 |
| `document_revisions` | 복구 가능한 불변 문서 내용 | 문서별 순차 버전 |
| `change_proposals` | AI 또는 사용자가 제안한 변경의 승인 대기 기록 | 기준/제안 리비전과 승인 결과 연결 |
| `features` | 계층형 기능명세와 개발 상태 | 부모 기능, 근거 문서 연결 |
| `acceptance_criteria` | 기능별 검증 가능한 완료 조건 | 기능에 종속 |
| `development_tasks` | 구현 작업과 진행 상태 | 기능에 종속 |
| `trace_links` | 기능·작업과 파일·브랜치·커밋·테스트 연결 | 범용 소스/대상 링크 |
| `comments` | 기획 항목별 메모 | 범용 대상 연결 |
| `activity_log` | 중요한 변경과 승인 이력 | 프로젝트 범위 감사 기록 |

식별자는 애플리케이션에서 생성한 UUID 문자열을 사용하고, 시간은 UTC ISO 8601 문자열로 저장한다. 문서 리비전은 수정하지 않고 새 버전을 추가한다. `documents.current_revision_id` 변경과 리비전 추가는 하나의 트랜잭션으로 처리한다.

## AI 경계

`AiPlanningProvider`는 대화 입력과 제한된 문서 컨텍스트를 받아 구조화된 변경안을 반환한다. 개발 모드는 동일한 인터페이스를 구현하는 결정적 로컬 생성기를 사용하며 화면에 개발 모드임을 명시한다. 외부 AI 도입 전에는 공급자, 비용, 전송 범위, 키 저장 방식을 사용자에게 설명하고 승인을 받는다.

AI 결과는 다음 순서로 처리한다.

1. 응답 스키마를 검증한다.
2. 기준 리비전과 제안 내용을 별도 리비전 및 `pending` 변경안으로 저장한다.
3. 비교 화면에서 추가·수정·삭제를 보여준다.
4. 승인 시 현재 리비전을 교체하고 활동 기록을 남긴다.
5. 거절 시 원문은 유지하고 거절 사유와 시각만 기록한다.

## Git과 외부 파일 경계

Git 연동은 읽기부터 시작하며 저장소 경로, 브랜치와 커밋 해시를 추적 링크로 저장한다. 명령은 문자열 셸 조합이 아니라 검증된 인자 배열로 실행한다. 외부 파일 쓰기와 커밋 생성은 변경 대상과 diff를 먼저 보여주고 별도 사용자 확인을 받는 후속 기능으로 둔다.

## 단계별 구현 계획

### 0단계: 기반 확정

- 아키텍처, 초기 SQLite 스키마와 마이그레이션 규칙 확정
- TypeScript strict, React, Tauri 기본 프로젝트 초기화
- 저장소 포트와 SQLite 어댑터의 통합 테스트 기반 구성

### 1단계: 첫 수직 기능

- 프로젝트 생성·목록·다시 열기
- 아이디어 입력과 결정적 개발 모드 PRD 초안 생성
- PRD 편집, 리비전 저장과 재실행 후 조회
- 로딩, 빈 상태, 유효성 오류와 저장 실패 복구

### 2단계: 기능명세와 승인 흐름

- PRD에서 계층형 기능명세 제안
- 상태·중요도·역할·수용 기준 편집
- 변경 비교와 AI 변경안 승인·거절
- 코멘트와 활동 기록

### 3단계: 개발 추적

- 로컬 Git 저장소 읽기 연결
- 기능과 파일·브랜치·커밋·테스트 연결
- 수용 기준과 테스트 결과 기반 완료 판정
- 기획 변경 영향 후보 분석

### 4단계: 표현과 이동성

- Markdown/JSON 내보내기와 재가져오기 검토
- 유저플로우와 와이어프레임 문서 유형 추가
- Globeat 실제 자료로 범용성 검증

## 첫 수직 기능의 구체적 작업 범위

### 사용자 흐름

1. 앱을 처음 열면 프로젝트 없음 화면이 보인다.
2. 사용자가 이름과 아이디어를 입력해 로컬 프로젝트를 만든다.
3. 사용자가 `PRD 초안 만들기`를 선택하면 개발 모드 생성기가 목표, 사용자, 문제, 범위, 제외 범위, 성공 기준 섹션을 만든다.
4. 사용자가 초안을 편집하고 저장한다.
5. 앱을 종료하고 다시 열어 프로젝트와 마지막 저장 PRD를 조회한다.

### 완료 조건

- 빈 이름과 아이디어는 저장되지 않고 필드별 오류를 보여준다.
- 프로젝트와 PRD는 SQLite에 저장되고 재시작 후 동일한 내용으로 복원된다.
- 저장할 때마다 불변 리비전이 추가되며 이전 리비전을 읽을 수 있다.
- 개발 모드 생성은 외부 네트워크를 사용하지 않으며 UI에 명시된다.
- 데이터베이스 오류 시 입력을 잃지 않고 재시도할 수 있다.
- 프로젝트 생성·리비전 저장·재조회에 대한 통합 테스트가 통과한다.
- 관련 제품 문서와 진행 문서가 함께 갱신된다.

### 범위 밖

- 실제 외부 AI 호출
- 파일 첨부, Git 쓰기, 자동 커밋
- 기능명세 자동 생성과 변경안 비교 UI
- 유저플로우와 와이어프레임 편집기

## 다음 개발 순서

1. 사용자가 React/Tauri 초기화와 필요한 무료 오픈소스 패키지 설치 범위를 확인한다.
2. 기본 앱을 생성하고 strict 타입 검사, 린트와 테스트 명령을 고정한다.
3. 초기 마이그레이션을 Tauri에 연결하고 프로젝트 저장소 통합 테스트를 작성한다.
4. 프로젝트 생성 화면부터 저장·재조회까지 수직으로 연결한다.
