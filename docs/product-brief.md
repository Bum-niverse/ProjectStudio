# ProjectStudio 제품 초안 v0.1

## 기획 품질 게이트

ProjectStudio는 산출물 개수만으로 상세도를 판단하지 않는다. 생성 결과를 웹·앱, 머신러닝, 데이터 분석 또는 일반 소프트웨어로 분류하고 공통 추적성과 프로젝트 유형별 실패 위험을 검사한다. 검사기는 결과를 자동 확정하거나 삭제하지 않고 근거와 수정 권고를 제시하며, 사용자가 검토한 뒤 다음 단계로 진행하는 승인 모델을 유지한다.

## 한 줄 정의

AI와 함께 제품을 기획하고 각 요구사항이 코드·커밋·테스트를 거쳐 완료되는 과정까지 시각적으로 추적하는 개인용 로컬 프로그램이다.

## 단계

화면형 제품: `유형·아이디어 → PRD → 기능명세 → 유저플로우 → 시스템 설계(선택) → 내보내기`

비화면형 제품: `유형·아이디어 → PRD → 기능명세 → 실행 파이프라인 → 시스템 설계(선택) → 내보내기`

## 첫 번째 사용자

개발 경험이 많지 않지만 AI와 함께 실제 제품을 만들고, 기획과 코드가 어긋나지 않게 관리하려는 프로그램 소유자 본인이다.

앱은 시작 시 GitHub 로그인 잠금 화면을 먼저 표시하고 로그인 전에는 프로젝트 SQLite를 조회하지 않는다. 인증은 GitHub CLI가 Windows 자격 증명 저장소에 보관한 세션을 재사용하며 ProjectStudio는 OAuth 토큰을 별도로 저장하지 않는다. 모든 GitHub 사용자는 자신의 Windows 계정에 저장된 독립 로컬 작업대를 열 수 있고, GitHub 사용자 ID `128395576` (`Bum-niverse`)에만 개발자 모드를 제공한다. 이 로그인은 앱 진입을 제한하지만 SQLite 파일 자체를 암호화하지 않으므로 저장 파일의 접근 제어는 Windows 사용자 계정 보안에 의존한다.

소유자 계정으로 로그인하면 상단에 개발자 모드 ON/OFF가 표시된다. 개발자 모드를 켠 상태에서 앱이 로컬 Tauri 개발 서버(`:1420`)로 실행 중이면 `실시간 반영 연결됨`을 표시하고 Vite HMR로 프론트엔드 수정사항을 즉시 반영한다. 일반 실행 파일에서는 개발 빌드가 필요하다는 상태를 표시하며 토글 자체가 배포 앱을 개발 서버로 전환하지는 않는다.

## MVP 완료 기준

- 프로젝트를 로컬에 생성하고 다시 열 수 있다.
- AI 대화 또는 직접 입력으로 PRD를 만들고 편집할 수 있다.
- PRD에서 계층형 기능명세를 만들 수 있다.
- 각 기능에 상태, 중요도, 역할과 수용 기준을 기록할 수 있다.
- 변경 내역을 비교하고 승인·거절할 수 있다.
- Markdown과 JSON으로 내보낼 수 있다.
- 하나의 Git 저장소를 연결하고 기능과 커밋·테스트 상태를 연결할 수 있다.

유저플로우와 시스템 설계는 핵심 문서 모델이 안정된 뒤 추가한다.

## 첫 수직 기능

프로젝트 이름과 아이디어를 로컬에 저장하고, 외부 전송이 없는 개발 모드 생성기로 구조화된 PRD 초안을 만든다. 사용자는 초안을 편집·저장하고 앱을 다시 실행한 뒤 마지막 리비전을 조회할 수 있다. 상세 범위와 완료 조건은 [MVP 아키텍처](mvp-architecture.md)에 기록한다.


프로젝트와 초기 PRD의 SQLite 저장·재조회, PRD 편집, 새 불변 리비전, 계층형 기능명세와 상태·중요도·역할·수용 기준 편집을 구현했다.


3단계 기능명세는 동일한 기능 데이터를 목록·트리·마인드맵으로 전환해 볼 수 있다. 트리는 전체 구조와 루트 바로 아래 대주제별 시트를 제공하고, 한 부모의 하위 기능을 직교 곡선 연결선으로 분기해 화면·행동·결과·검증 규칙의 계층을 읽을 수 있게 한다. 기본 정렬은 연결 관계 판독을 위해 노드 간격을 넓게 펼치고 좁은 정렬은 같은 계층을 압축한다. 트리와 마인드맵은 노드 이동·화면 이동·확대/축소를 지원하고 보기별 배치를 보존하며, 기능 데이터 자체는 SQLite를 단일 원본으로 사용한다.

4단계 유저플로우는 기능명세 노드를 복제하지 않고 실제 화면 이동을 별도 모델로 생성한다. 사용자에게 직접 가치가 없는 운영 정책·내부 검토 대주제는 lane에서 제외하고, 요구사항별 가로 스윔레인 안에 대단계·화면·행동·분기·결과를 depth 열로 정렬한다. 노드에는 lane, depth, 부모, 연결 기능명세와 분기 조건을 저장하며 사용자 이동 좌표는 자동 정렬을 다시 실행하기 전까지 보존한다. 데이터베이스 저장, RLS, URL 안전 검증, 토큰 갱신, 캐시와 내부 권한 검사는 유저플로우 노드로 만들지 않는다.

개발 모드에서 생성한 최초 기능명세와 트리·마인드맵별 노드 위치는 SQLite에 저장되어 앱을 다시 열어도 복원된다.

개발 모드 기능명세의 상세 문서는 동일한 한 줄 템플릿을 반복하지 않는다. 상위 기능의 역할·목적을 사용해 정상 흐름의 시작·완료 상태, 입력·권한·외부 서비스 오류와 복구, 저장·재조회·소유권·변경 이력을 각각 설명하고 문서마다 세 개 이상의 검증 가능한 수용 기준을 만든다.

1단계는 프로젝트 이름과 아이디어 입력만 담당한다. 생성 후 작업대로 자동 이동하며 기본 화면은 2단계 PRD다. 기능명세는 3단계를 선택했을 때만 표시한다.

각 단계는 작업대 안의 탭이 아니라 화면 전체를 사용하는 독립 페이지다. 프로젝트 생성 즉시 PRD 페이지로 이동하고, 사용자가 PRD를 확인·수정한 뒤 다음 버튼으로 기능명세 페이지에 진입한다. 마인드맵은 중앙 대주제를 기준으로 기능들이 원 둘레로 방사되는 별 형태를 기본 배치로 사용한다.

기능명세 페이지는 Document view, Tree view와 Mind map view를 제공한다. Document view는 요구사항·기능 목록·상세 문서의 3단 구조이며 기능명, 설명, 상태, 중요도, 역할과 수용 기준을 편집한다. Tree view는 부모가 자식 묶음의 중앙에 오는 좌→우 계층을 기본으로 하며 자유 이동과 근접 정렬선 자석 스냅을 지원한다.

Tree와 Mind map의 모든 노드는 왼쪽 입력점과 오른쪽 출력점을 사용한다. 출력점에서 다른 노드 입력점으로 연결하면 부모·자식 관계를 변경하며 자기 연결과 순환 관계는 차단한다. 두 보기에서 노드를 선택하면 우측 상세 편집 패널을 열어 Document view와 동일한 문서를 수정한다. 개발 모드 초기 구조는 요구사항·기능·상세 기능의 3단계와 약 40개 이상의 문서를 생성한다.

트리 기본 정렬은 요구사항과 기능 묶음을 위아래로 구분하되, 한 기능에 속한 기본 흐름·오류 복구·저장 이력 같은 마지막 상세 문서를 동일 행에서 오른쪽으로 연속 배치한다. 상세 문서 수가 늘어나도 전체 높이보다 가로 작업공간을 우선 사용해 캔버스를 아래로 스크롤하지 않고 전체 구조를 한눈에 볼 수 있게 한다.

대주제 전환 지점에는 기능 행보다 큰 수직 여백을 두고, 각 대주제는 서로 다른 고대비 색상을 사용한다. 대주제 색상은 해당 가지의 하위 기능과 연결선에 함께 적용하되 상태·중요도 텍스트를 유지해 색상만으로 의미를 전달하지 않는다. 주요 CTA는 강조 배경과 대비되는 글자, 보조 행동은 패널 배경과 테두리, 위험 행동은 오류 색상과 설명 문구로 구분한다.

Codex 연동 산출물은 연결된 저장소의 `.projectstudio` 아래에 안정적인 ID 기반 Markdown과 JSON으로 기록하고 마지막 저장 이후 변경 항목은 `changes/latest.json`으로 제공한다. 상세 계약은 [Codex 동기화 계약](codex-sync-contract.md)에 정의한다.

설정 페이지는 Pure Black, VS Code Light, Neutral Gray, VS Code Dark의 네 가지 테마를 제공하고 선택을 이 컴퓨터에 유지한다. VS Code Light/Dark는 Microsoft의 Light Modern/Dark Modern workbench 색상 토큰을 기준으로 배경·패널·입력·테두리·본문·보조 글씨·강조색을 함께 전환해 화면 안팎의 대비를 일관되게 유지한다. Codex·Git·GitHub CLI의 설치 및 GitHub CLI 인증 상태를 로컬에서 확인하며 토큰이나 계정 응답은 저장하지 않는다. 프로젝트별 로컬 Git 저장소와 GitHub 원격 주소를 지정하고 사용자가 명시적으로 동기화할 때만 `.projectstudio` 문서를 쓴다.

모든 페이지의 카드·입력·보조 문구·선택 상태는 동일한 테마 토큰을 사용하며 밝은 테마에서도 흰 글씨가 밝은 배경에 남지 않아야 한다. 데스크톱 폭이 줄어들면 상단 상태, 단계 탭, 설정 연결 폼과 내보내기 체크 목록은 경계를 넘기지 않고 의도된 단위로 재배치한다. 긴 문서명은 목록에서는 한 줄 말줄임으로, 설명과 선택 항목에서는 자연스러운 여러 줄로 표시한다.

기본 UI·문서 글꼴은 SIL Open Font License 1.1의 IBM Plex Sans KR Regular·Medium·SemiBold를 앱 내부 자산으로 포함해 오프라인에서도 동일하게 표시한다. 설정에서 IBM Plex Sans KR과 운영체제 기본 글꼴을 즉시 전환하고 선택을 이 컴퓨터에 저장한다. 코드·안정 ID·원문 출력은 가독성을 위해 고정폭 글꼴을 유지한다.

설정의 도구 상태 영역은 Claude CLI, Codex CLI, Antigravity, Git, GitHub CLI와 GitHub 인증을 개별 카드로 표시한다. 사용자는 작은 재시도 버튼으로 로컬 설치·인증 상태를 다시 확인하며, ProjectStudio는 이 확인 과정에서 자격 증명이나 API 키를 수집하지 않는다. 프로젝트 저장소와 GitHub 원격 설정은 별도 영역으로 유지한다.

LLM 도구는 `CLAUDE CLI`, `CODEX CLI`, `ANTIGRAVITY`, `로컬 LLM · OLLAMA` 접이식 연결 카드로 관리한다. 각 카드는 사용자가 CLI 실행 파일 이름 또는 절대 경로를 직접 지정하고 저장한 뒤 개별 연결 확인을 실행한다. 연결 확인은 `--version` 정보만 읽고 프로젝트 문서를 전송하지 않는다.

기능명세의 AI 변경안은 현재 기능 스냅샷과 제안 스냅샷을 별도로 보존한다. 사용자는 설명·상태·중요도·역할·수용 기준의 전후 내용을 비교하고 승인 또는 거절한다. 승인 전에 원본을 수정하지 않으며, 변경안 생성 이후 원본이 수정된 경우 오래된 변경안 승인을 차단한다. 승인·거절 결과와 거절 사유는 활동 기록에 남긴다. 실제 AI 공급자 연결 전에는 외부 전송이 없는 개발 모드 제안만 생성한다.

4단계 유저플로우는 3단계 기능명세를 입력으로 사용해 요구사항별 수평 스윔레인을 만든다. 대주제 레인은 React Flow 부모 노드이며 내부 단계는 해당 레인의 자식으로 묶인다. 따라서 캔버스 이동·확대·축소 시 대주제와 단계가 같은 좌표계에서 움직이고, 단계는 소속 대주제 경계를 벗어나지 않는다. 각 레인에는 대단계, 화면, 행동, 분기와 결과가 좌우로 이어지고 상세 기능은 주 흐름에서 가지로 펼쳐진다. 모든 노드는 클릭 시 우측 편집 패널에서 이름·종류·세부 내용을 수정하며 위치·연결·문서는 SQLite에 보존한다.

유저플로우는 기능명세 상세 문서를 그대로 시각화하지 않는다. 각 대주제 안에서 실제 화면 → 사용자가 누르거나 입력하는 행동 → 다음 화면 또는 선택·분기 → 저장된 완료 상태를 긴 가로 흐름으로 연결하며, 구현과 무관한 기본 흐름·검증·이력 문서 노드는 만들지 않는다. 대주제마다 독립된 색상을 레인·노드·연결선에 적용하고 서로 직접 이어져야 하는 단계만 연결한다.

각 유저플로우·실행 파이프라인 노드는 개발 완료 여부를 체크할 수 있다. 체크 결과는 노드의 실행 메타데이터로 SQLite에 즉시 저장하며, 헤더에는 전체 완료 수와 백분율을, 대주제 시트에는 스윔레인별 `완료/전체` 수를 표시한다. 완료 표시는 구현 사실을 자동 추정하지 않고 사용자가 확인한 상태만 보존한다.

사용자가 삭제한 유저플로우 노드는 삭제 tombstone을 SQLite에 남긴다. 기능명세에서 자동 생성 가능한 노드라도 이후 화면 진입이나 기본 정렬 과정에서 다시 나타나지 않으며, 명시적으로 같은 ID의 노드를 새로 만들 때만 삭제 상태를 해제한다.

유저플로우 연결선은 좌→우 직교 흐름을 유지하는 smooth-step으로 표시하고, 한 노드에서 여러 다음 화면으로 자연스럽게 분기한다. 기능명세의 부모·자식 연결선은 클릭해 선택할 수 있으며 선 근처의 삭제 전용 툴바에서 관계만 제거한다. 대상 기능과 하위 문서는 삭제하지 않고 독립된 요구사항으로 유지한다.










기능명세와 유저플로우의 시각 노드는 같은 조작 규칙을 사용한다. 노드를 선택하면 주변 툴바에서 하위/다음 노드 추가, 상세 편집과 삭제를 실행한다. 우측 상세 패널은 문서 필드와 색상 팔레트를 제공하며, 팔레트 선택은 별도의 문서 저장 동작 없이 즉시 화면에 반영하고 SQLite에 자동 저장한다. 드래그 프레임 좌표는 React Flow의 제어 상태에 즉시 반영하고 SQLite 저장은 놓을 때 한 번만 실행한다. 시작 임계값, 좌표 보간과 자동 스냅 없이 포인터를 따라가며, 마우스를 놓은 정확한 좌표를 확정한다. 원래 위치 복원은 사용자가 `기본 정렬`을 실행할 때만 수행한다.

선택된 기능명세·유저플로우 노드를 다시 클릭하면 선택이 해제되어 주변 툴바가 닫힌다. 유저플로우는 1920×1080 논리 작업공간을 고정 높이 캔버스 안에 맞춰 표시하며, 페이지를 길게 스크롤하는 대신 캔버스 이동과 확대·축소로 전체 흐름을 탐색한다. 캔버스 프레임 높이는 기능명세의 트리·마인드맵과 동일한 화면 기준을 사용한다.

유저플로우 상단에는 기능명세의 최상위 프로젝트 루트를 별도로 표시하고, 각 스윔레인은 노드의 저장 순서가 아니라 `linkedFeatureIds`가 가리키는 실제 최상위 기능 대분류에 소속시킨다. 연결 근거가 없는 사용자 정의 레인은 기존 이름과 내용을 보존하며 임의의 대분류에 순서대로 끼워 넣지 않는다. 대분류에는 실제 소속 노드가 있을 때만 레인을 표시한다.

기능명세 트리·마인드맵과 유저플로우 캔버스는 라이브러리 브랜드 표시를 노출하지 않는다. 오른쪽 아래에는 `기본 정렬 | 좁은 정렬`을 두고, 좁은 정렬은 계층 깊이·행·열 간격을 실제로 줄여 저장한다.

기존 와이어프레임 단계는 실제 사용 빈도가 없고 유저플로우·구현 작업과 역할이 중복되어 2026-07-14에 제거했다. 화면 설계가 필요한 프로젝트는 유저플로우의 화면 노드를 기준으로 별도 구현 도구에서 작업하며, ProjectStudio는 요구사항·흐름·시스템 설계·코드 추적에 집중한다.

각 Codex 블록은 이름만 나열하지 않고 데스크톱 1440×900 또는 모바일 390×844 캔버스의 x·y·width·height 좌표를 포함한다. ProjectStudio는 좌표 범위를 검증한 뒤 헤더, 검색 입력, 이미지·지도 자리, 지표 카드, 폼, 표·목록, 상세 패널과 주요 버튼 형태의 저충실도 UI를 실제 한 화면 배치로 그린다.


6단계 시스템 설계는 기능명세·유저플로우를 서비스, 저장소, 외부 시스템과 연결하고 JSON snapshot 리비전으로 저장한다. 필요하지 않은 프로젝트는 건너뛸 수 있다. 7단계 내보내기는 프로젝트 개요, PRD, 기능명세·수용 기준, 유저플로우와 시스템 설계를 CSV 묶음, A4 PDF 기획 보고서, JSON·Mermaid와 Markdown 프로젝트 문맥으로 생성한다. Codex·Claude·Antigravity·범용 LLM마다 `project-context.md`를 먼저 읽도록 실행 프롬프트를 별도 Markdown으로 만든다. PDF 생성은 로컬 Windows 인쇄 엔진을 사용하며 외부 서버로 문서를 전송하지 않는다.

내보내기 화면의 `완료 및 종료`는 비활성 자리표시자가 아니라 현재 ProjectStudio 창을 닫아 프로그램을 종료한다.

완료 종료는 프론트엔드 창 권한에 의존하지 않고 Tauri Rust 프로세스 종료 명령을 사용한다. 종료 요청 자체가 실패한 경우에는 버튼이 무반응처럼 보이지 않도록 내보내기 화면에 재시도 가능한 오류를 표시한다.

공개 Windows 베타는 GitHub Releases에서 NSIS EXE와 MSI 설치 패키지로 배포한다. 설치형 사용자는 개발 런타임 없이 실행하며 각 Windows 계정의 앱 데이터 폴더에 SQLite를 자동 생성한다. 코드 서명 인증서를 적용하기 전에는 Windows SmartScreen 경고가 나타날 수 있음을 설치 안내에 표시하고, Release에 SHA-256 체크섬을 함께 제공한다. 소스와 설치 파일은 공개 GitHub 저장소에서 누구나 확인할 수 있다. 자동 업데이트 서버를 두지 않는 초기 단계에서는 버전을 확인한 뒤 새 설치 파일로 덮어 설치하며 기존 앱 데이터 폴더를 유지한다.
