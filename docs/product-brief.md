# ProjectStudio 제품 초안 v0.1

## 한 줄 정의

AI와 함께 제품을 기획하고 각 요구사항이 코드·커밋·테스트를 거쳐 완료되는 과정까지 시각적으로 추적하는 개인용 로컬 프로그램이다.

## 단계

`아이디어 → PRD → 기능명세 → 유저플로우 → 와이어프레임 → 개발 작업 → 코드/커밋 → 테스트 → 완료`

## 첫 번째 사용자

개발 경험이 많지 않지만 AI와 함께 실제 제품을 만들고, 기획과 코드가 어긋나지 않게 관리하려는 프로그램 소유자 본인이다.

## 첫 사용 프로젝트

Globeat의 기획 문서를 가져오고 개발 작업, 코드, 테스트와 완료 상태를 연결한다.

## MVP 완료 기준

- 프로젝트를 로컬에 생성하고 다시 열 수 있다.
- AI 대화 또는 직접 입력으로 PRD를 만들고 편집할 수 있다.
- PRD에서 계층형 기능명세를 만들 수 있다.
- 각 기능에 상태, 중요도, 역할과 수용 기준을 기록할 수 있다.
- 변경 내역을 비교하고 승인·거절할 수 있다.
- Markdown과 JSON으로 내보낼 수 있다.
- 하나의 Git 저장소를 연결하고 기능과 커밋·테스트 상태를 연결할 수 있다.

유저플로우와 와이어프레임은 핵심 문서 모델이 안정된 뒤 추가한다.

## 첫 수직 기능

프로젝트 이름과 아이디어를 로컬에 저장하고, 외부 전송이 없는 개발 모드 생성기로 구조화된 PRD 초안을 만든다. 사용자는 초안을 편집·저장하고 앱을 다시 실행한 뒤 마지막 리비전을 조회할 수 있다. 상세 범위와 완료 조건은 [MVP 아키텍처](mvp-architecture.md)에 기록한다.

프로젝트와 초기 PRD의 SQLite 저장·재조회, PRD 편집과 새 불변 리비전 저장을 구현했다. 다음 작업은 PRD에서 계층형 기능명세를 만들고 상태·중요도·역할·수용 기준을 편집하는 흐름이다.

3단계 기능명세는 동일한 기능 데이터를 목록·트리·마인드맵으로 전환해 볼 수 있다. 트리와 마인드맵은 노드 이동·화면 이동·확대/축소를 지원하고 보기별 배치를 보존하며, 기능 데이터 자체는 SQLite를 단일 원본으로 사용한다.

개발 모드에서 생성한 최초 기능명세와 트리·마인드맵별 노드 위치는 SQLite에 저장되어 앱을 다시 열어도 복원된다.

1단계는 프로젝트 이름과 아이디어 입력만 담당한다. 생성 후 작업대로 자동 이동하며 기본 화면은 2단계 PRD다. 기능명세는 3단계를 선택했을 때만 표시한다.

각 단계는 작업대 안의 탭이 아니라 화면 전체를 사용하는 독립 페이지다. 프로젝트 생성 즉시 PRD 페이지로 이동하고, 사용자가 PRD를 확인·수정한 뒤 다음 버튼으로 기능명세 페이지에 진입한다. 마인드맵은 중앙 대주제를 기준으로 기능들이 원 둘레로 방사되는 별 형태를 기본 배치로 사용한다.

기능명세 페이지는 Document view, Tree view와 Mind map view를 제공한다. Document view는 요구사항·기능 목록·상세 문서의 3단 구조이며 기능명, 설명, 상태, 중요도, 역할과 수용 기준을 편집한다. Tree view는 부모가 자식 묶음의 중앙에 오는 좌→우 계층을 기본으로 하며 자유 이동과 근접 정렬선 자석 스냅을 지원한다.

Tree와 Mind map의 모든 노드는 왼쪽 입력점과 오른쪽 출력점을 사용한다. 출력점에서 다른 노드 입력점으로 연결하면 부모·자식 관계를 변경하며 자기 연결과 순환 관계는 차단한다. 두 보기에서 노드를 선택하면 우측 상세 편집 패널을 열어 Document view와 동일한 문서를 수정한다. 개발 모드 초기 구조는 요구사항·기능·상세 기능의 3단계와 약 40개 이상의 문서를 생성한다.

Codex 연동 산출물은 연결된 저장소의 `.projectstudio` 아래에 안정적인 ID 기반 Markdown과 JSON으로 기록하고 마지막 저장 이후 변경 항목은 `changes/latest.json`으로 제공한다. 상세 계약은 [Codex 동기화 계약](codex-sync-contract.md)에 정의한다.

설정 페이지는 Pure Black, VS Code Light, Neutral Gray, VS Code Dark의 네 가지 테마를 제공하고 선택을 이 컴퓨터에 유지한다. VS Code Light/Dark는 Microsoft의 Light Modern/Dark Modern workbench 색상 토큰을 기준으로 배경·패널·입력·테두리·본문·보조 글씨·강조색을 함께 전환해 화면 안팎의 대비를 일관되게 유지한다. Codex·Git·GitHub CLI의 설치 및 GitHub CLI 인증 상태를 로컬에서 확인하며 토큰이나 계정 응답은 저장하지 않는다. 프로젝트별 로컬 Git 저장소와 GitHub 원격 주소를 지정하고 사용자가 명시적으로 동기화할 때만 `.projectstudio` 문서를 쓴다.

설정의 도구 상태 영역은 Claude CLI, Codex CLI, Antigravity, Git, GitHub CLI와 GitHub 인증을 개별 카드로 표시한다. 사용자는 작은 재시도 버튼으로 로컬 설치·인증 상태를 다시 확인하며, ProjectStudio는 이 확인 과정에서 자격 증명이나 API 키를 수집하지 않는다. 프로젝트 저장소와 GitHub 원격 설정은 별도 영역으로 유지한다.

기능명세의 AI 변경안은 현재 기능 스냅샷과 제안 스냅샷을 별도로 보존한다. 사용자는 설명·상태·중요도·역할·수용 기준의 전후 내용을 비교하고 승인 또는 거절한다. 승인 전에 원본을 수정하지 않으며, 변경안 생성 이후 원본이 수정된 경우 오래된 변경안 승인을 차단한다. 승인·거절 결과와 거절 사유는 활동 기록에 남긴다. 실제 AI 공급자 연결 전에는 외부 전송이 없는 개발 모드 제안만 생성한다.

4단계 유저플로우는 3단계 기능명세를 입력으로 사용해 요구사항별 수평 스윔레인을 만든다. 대주제 레인은 React Flow 부모 노드이며 내부 단계는 해당 레인의 자식으로 묶인다. 따라서 캔버스 이동·확대·축소 시 대주제와 단계가 같은 좌표계에서 움직이고, 단계는 소속 대주제 경계를 벗어나지 않는다. 각 레인에는 대단계, 화면, 행동, 분기와 결과가 좌우로 이어지고 상세 기능은 주 흐름에서 가지로 펼쳐진다. 모든 노드는 클릭 시 우측 편집 패널에서 이름·종류·세부 내용을 수정하며 위치·연결·문서는 SQLite에 보존한다.

첫 실제 프로젝트 Globeat은 세계의 실제 장소에 플레이리스트를 꽂아 발견하고 공유하는 음악 지도다. 이름과 아이디어를 입력하면 인증·온보딩, 지구본 탐색·장소 발견, 플레이리스트 만들기·수정, 상세·외부 재생, 내 라이브러리, 신고·콘텐츠 관리의 6개 기능군으로 구체화한다. 각 기능군은 실행·검증·저장 이력의 상세 문서와 레인을 넘나드는 유저플로우 단계로 자동 확장한다.

기능명세와 유저플로우의 시각 노드는 같은 조작 규칙을 사용한다. 노드를 선택하면 주변 툴바에서 하위/다음 노드 추가, 상세 편집과 삭제를 실행한다. 우측 상세 패널은 문서 필드와 색상 팔레트를 제공하며, 팔레트 선택은 별도의 문서 저장 동작 없이 즉시 화면에 반영하고 SQLite에 자동 저장한다. 드래그 중에는 포인터를 즉시 따라가며 놓은 위치에 감속 정착하고, 원래 위치 복원은 사용자가 `기본 정렬`을 실행할 때만 수행한다.

선택된 기능명세·유저플로우 노드를 다시 클릭하면 선택이 해제되어 주변 툴바가 닫힌다. 유저플로우는 1920×1080 논리 작업공간을 고정 높이 캔버스 안에 맞춰 표시하며, 페이지를 길게 스크롤하는 대신 캔버스 이동과 확대·축소로 전체 흐름을 탐색한다. 캔버스 프레임 높이는 기능명세의 트리·마인드맵과 동일한 화면 기준을 사용한다.

5단계 와이어프레임은 유저플로우의 대단계·화면 노드를 생성 후보 페이지로 자동 수집한다. 사용자는 대주제별 목록을 접고 펼치며 필요한 페이지만 선택하고, 데스크톱·모바일 디바이스와 생성 도구, 추가 요청사항을 지정한다. 외부 전송이 없는 로컬 프리뷰는 화면 목적에 맞는 탐색·폼·목록·상세·행동 블록을 즉시 구성하고 페이지 목록, 중앙 미리보기와 상세 패널에서 결과를 확인한다. Claude·Codex·Antigravity·Ollama는 로컬 설치 상태를 표시하며 연결되지 않은 도구로는 생성을 시작하지 않는다. 실제 외부 CLI 호출 전에는 선택 문서가 해당 도구로 전달된다는 사실을 화면에 표시한다.
