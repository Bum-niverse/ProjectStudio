# ProjectStudio 개발 진행

## 2026-07-14 프로젝트 유형 선택 단순화

- 새 프로젝트 선택 유형을 웹 서비스·모바일 앱·머신러닝·데이터 분석 4개로 축소
- 백엔드는 독립 프로젝트 유형이 아니라 웹·모바일의 기능명세와 시스템 설계 구성요소로 처리
- 데스크톱·백엔드/CLI·기타로 저장된 기존 프로젝트는 데이터 손실 없이 열 수 있도록 내부 타입과 표시 이름 유지

## 2026-07-14 미사용 와이어프레임 단계 제거

- 실제 개인 기획 흐름에서 사용하지 않고 유저플로우·구현 단계와 역할이 겹치던 와이어프레임 화면과 생성 경로 제거
- 프로젝트 단계는 `프로젝트 → PRD → 기능명세 → 유저플로우/실행 파이프라인 → 시스템 설계 → 내보내기`로 단순화
- 시스템 설계의 와이어프레임 연결 UI와 Codex·Tauri 와이어프레임 명령 제거
- 기존 SQLite 작업공간이 깨지지 않도록 `0007_wireframe_pages.sql` 마이그레이션 이력과 시스템 설계 JSON의 레거시 필드는 유지

## 2026-07-14 프로젝트 유형 기반 단계 구성

- 생성 시 웹, 모바일, 데스크톱, 백엔드·CLI·자동화, 머신러닝, 데이터 분석, 기타 소프트웨어 유형을 필수 선택
- 유형을 SQLite에 저장하고 기존 프로젝트는 `자동 감지`로 안전하게 이관
- 화면형 제품은 유저플로우를 사용하고 시스템 설계로 바로 이동
- 머신러닝·데이터 분석·백엔드 도구는 입력→검증→처리→평가·산출물 실행 파이프라인을 생성
- Codex 생성과 품질 검사가 사용자의 선택 유형을 자동 추론보다 우선 사용

## 2026-07-14 프로젝트 유형별 기획 품질 검사

- Codex 생성 직후 웹·앱, 머신러닝, 데이터 분석, 일반 소프트웨어 유형을 자동 분류
- 기능 계층·수용 기준·가시적 사용자 흐름·고립 노드·시스템 상세도·추적 링크를 공통 검사
- 앱의 상태·권한, ML의 데이터 출처·분할·누수·평가·재현성, 분석의 스키마·병합·무결성·계보를 유형별 검사
- 검사 결과를 삭제하지 않고 `통과 / 검토 필요 / 보완 필요` 점수와 상위 권고로 PRD 화면에 표시
- 개발 동기, 기술 선택, 시행착오와 2026-07-10부터의 전환점을 포트폴리오 기록으로 정리

## 2026-07-13 아이디어 기반 상세 PRD 생성

- 일반 프로젝트의 범용 문구를 제거하고 입력 아이디어를 제품 목표·배경·문제·해결·시나리오·지표·완료 기준·리스크·제외 범위로 확장
- 데이터·ML 아이디어는 데이터 품질, 미래 정보 누수, 기준선 비교, 시간 순서 검증, 재현성과 결과 오해 방지를 포함하는 상세 PRD 생성
- 일반 제품 아이디어는 원문을 보존하고 확인되지 않은 사용자·시장·기기 정보는 확정하지 않고 검토 필요로 표시
- 외부 LLM이나 API가 없어도 동일한 입력에서 재현 가능한 PRD를 생성하며 기존 CLI는 이후 선택적 고도화 경로로 유지

## 2026-07-13 새 프로젝트 아이디어 기반 산출물 생성

- 일반 프로젝트 기능명세가 ProjectStudio 자체 기능을 복제하던 고정 시드를 제거하고 프로젝트 이름·아이디어에서 제품형 또는 데이터·ML형 구조를 선택
- 데이터·ML 프로젝트는 데이터 품질, 누수 없는 피처·레이블, 기준선, 시간 순서 검증, 결과 한계와 재현성을 공통 구조로 생성
- 정확히 일치하는 이전 43개 자동 시드만 안전하게 교체하고 사용자 편집 기능명세는 보존
- 유저플로우 생성 버전을 갱신해 교체된 기능명세에서 대주제별 흐름을 다시 구성

## 2026-07-13 공통 타이포그래피·기능명세 캔버스 회귀 보정

- 한글 제목과 설명은 임의 음절에서 끊지 않고 단어 단위로 줄바꿈하며, 좁은 폭에서는 긴 단어만 안전하게 분리
- 기능명세 노드 제목은 두 줄까지 표시하고 상태 메타데이터와 겹치지 않도록 공통 노드 높이 확보
- 새 프로젝트와 기존 프로젝트 모두 대주제별 색상을 하위 계층과 연결선까지 일관되게 재계산하는 버전 마이그레이션 적용
- 기능명세 트리·마인드맵도 테마와 글꼴이 반영된 뒤 화면 맞춤을 재실행해 테마 전환 시 캔버스 소실 예방

## 2026-07-13 테마 전환 후 시스템 캔버스 안정화

- 제공된 17.5초 화면 녹화를 프레임 단위로 확인해 Pure Black 복귀 후 비동기 캔버스 초기화 시점의 소실 재현
- React Flow 초기화 직후 두 번의 렌더 프레임을 기다려 테마·글꼴·노드 크기 계산이 끝난 다음 화면 맞춤 적용
- 초기 `fitView`에도 동일한 padding과 최대 확대율을 지정해 테마별 계산 차이 제거

## 2026-07-13 시스템 설계 빈 viewport 복구

- C4 수준, 관점, 정렬 패턴과 표시 노드 집합이 바뀌면 React Flow를 현재 노드 기준으로 다시 맞춤
- 노드 수와 연결 수는 표시되지만 이전 viewport 밖에 배치되어 빈 캔버스로 보이던 문제 수정
- 노드 드래그 중에는 자동 화면 맞춤이 실행되지 않아 사용자가 조정한 확대·이동 상태 유지

## 2026-07-13 기능명세 기반 분기·합류 자동 생성

- 상위 기능 아래의 복수 대안 경로를 자동 감지해 한 노드에서 여러 경로로 분기하는 유저플로우 생성
- 콜백·확정·완료·공통 후처리 성격의 기능을 합류 지점으로 추론해 각 분기 결과를 다시 연결
- 분기 수에 맞춰 레인 높이와 노드 세로 간격을 자동 계산하고 기존 프로젝트에는 레이아웃 v4로 재생성
- Globeat 인증 흐름에서 Google·Meta·이메일 가입·로그인이 분기되고 인증 콜백에서 합류하는 회귀 테스트 추가

## 2026-07-13 분기형 연결선 라우팅

- 유저플로우와 시스템 설계 연결선을 대각선 단선이 아닌 좌→우 직교 라우팅으로 변경
- 하나의 노드에서 여러 노드로 이어질 때 공통 출력 구간에서 자연스럽게 분기되도록 완만한 모서리 적용
- 연결선 라벨 제거, 테마 대비와 클릭 기반 상세 편집 동작은 그대로 유지

## 2026-07-13 그래프 가독성·테마 대비 보정

- 유저플로우와 시스템 설계 연결선을 라벨 없는 직선으로 통일하고 선택 시 상세 편집 패널에서 내용 확인
- 모든 테마에 노드 surface와 연결선 대비 토큰을 추가해 밝은·어두운 캔버스에서 구조가 사라지지 않도록 수정
- 대주제 시트의 세로 작업 영역과 노드 가로 간격을 확대하고 시트 탭 사이에 명확한 구분선 추가
- 유저플로우 레이아웃 버전을 갱신해 기존 프로젝트에도 넓은 기본 좌표를 한 번 적용

## 2026-07-13 유저플로우 시트·시스템 관계 라벨

- 유저플로우 기본 보기를 대주제별 시트로 전환하고 전체 지도·연결 집중의 세 가지 탐색 방식 제공
- 시트는 첫 단계부터 읽을 수 있는 크기를 유지한 채 가로 이동하고, 전체 지도는 전용 소형 노드와 대주제 제목 여백 사용
- 시스템 설계의 행·열 간격을 확대하고 연결 설명은 선 위에서 축약 표시하며 선택한 연결은 전체 문구 표시

## 2026-07-13 유저플로우 집중 보기

- 전체 흐름에서 노드를 선택하면 이전·다음 2단계와 해당 레인만 확대하는 집중 보기 추가
- 전체 보기 복귀, 현재 표시 단계 수, 집중 상태를 명시하고 연결선을 직각 경로로 변경
- 집중 보기에서는 전체 레인 크기가 아니라 표시 노드에 맞춰 viewport를 계산해 긴 프로젝트의 글자 겹침을 완화

## 2026-07-13 시스템 설계 연결선·문구 겹침 수정

- 직선 연결을 여유 있는 직각 경로로 변경해 같은 열의 노드 본문을 연결선이 가로지르지 않도록 수정
- edge 라벨에 불투명한 테마 배경과 안쪽 여백을 적용하고 세로 노드 간격을 확대

## 2026-07-13 시스템 설계 캔버스 표시 회귀 수정

- React Flow 내부 renderer·pane을 덮던 불투명 테마 배경을 제거해 시스템 노드, 연결선과 배경 격자가 다시 표시되도록 수정
- 캔버스 외곽만 테마 배경을 사용하도록 selector 경계를 회귀 테스트로 고정

## 2026-07-13 시스템 설계 인텔리전스 MVP

- C4 parent 계층, 런타임 정상·실패·복구 시나리오, 품질 속성·제약과 ADR 편집 추가
- 리비전 구조 비교, 요구사항 연결 후보 승인, 연결성·추적성·복원력 점수와 안티패턴 검토 추가
- 제한된 import/use 근거 수집과 노드별 구현·커밋·배포 상태 추적 추가
- PlantUML, Structurizr DSL, runtime sequence Mermaid와 ADR Markdown 내보내기 추가

## 2026-07-13 C4·런타임·구현 drift 확장

- 하나의 시스템 모델에서 Context, Container, Component, Code 수준을 점진적으로 탐색하는 C4 drill-down을 추가했다.
- 런타임 연결 순서와 비동기 흐름을 시각적으로 구분하고 노드에서 C4 수준을 편집할 수 있다.
- 연결된 로컬 Git 저장소 안에서 코드·테스트 상대 경로와 제한된 glob을 읽기 전용으로 검사해 구현 일치·경로 누락·연결 없음 상태를 표시한다.

## 2026-07-13 관점·패턴 기반 시스템 설계 정렬

- 단일 JSON 모델에 `viewType`(구조·런타임·배포·개발)과 `architecturePattern`(자동·계층·허브·파이프라인·이벤트·배포)을 추가했다.
- 자동 감지는 노드 유형과 연결 구조를 분석하고, 선택한 패턴은 캔버스 좌표만 다시 계산한다. 사용자가 저장하기 전에는 기존 불변 리비전을 변경하지 않는다.
- 기존 리비전은 구조 뷰·자동 정렬 기본값으로 호환하며 Codex 제안은 설계 동인·품질 속성·제약·트레이드오프를 검토하도록 생성 지침을 강화했다.

## 2026-07-13 시스템 설계 캔버스

- 6단계 선택형 시스템 설계와 7단계 내보내기 흐름 추가
- React Flow 기반 컴포넌트·연결 편집, 자동 정렬, 검토 경고 구현
- SQLite JSON snapshot 리비전과 Codex 제안 승인·거절 분리 저장
- 기능명세·유저플로우·수동 와이어프레임 ID, 코드·테스트 경로 연결
- Markdown·JSON·Mermaid·PDF 요약 및 `.projectstudio` 동기화 추가
- 상세 설계와 제한 사항은 `docs/system-design.md`에 기록
- 그룹 경계 안의 일반 노드를 그룹과 같은 거리만큼 함께 이동
- 생성 와이어프레임 SQLite 영속 저장·재조회와 시스템 설계 체크박스 연결

## 현재 단계

프로젝트 생성부터 PRD, 기능명세, AI 변경안 검토, 유저플로우, 영속 와이어프레임, 선택형 시스템 설계와 7단계 내보내기까지 연결했다. 와이어프레임은 유저플로우 원본 화면별 안정 ID로 저장되며 시스템 설계 노드에서 직접 선택할 수 있다.
