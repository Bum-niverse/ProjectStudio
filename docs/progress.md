## 2026-07-14 Windows 마이그레이션 checksum 실행 오류 복구

- Windows `core.autocrlf`가 SQL 마이그레이션을 CRLF로 체크아웃해 SQLx checksum이 달라지고 앱이 시작 전에 종료되던 원인 확인
- 기존 SQLite와 SQL 내용을 변경하지 않고 모든 마이그레이션 파일을 최초 적용 당시의 LF 바이트로 복원
- `.gitattributes`에서 마이그레이션 SQL의 LF를 강제하고 SHA-384 manifest 기반 불변성 검사를 공식 검증에 추가
- 기존 사용자 데이터베이스로 개발 앱을 다시 실행해 12개 마이그레이션 검증과 창 응답 상태 확인

- 시스템 설계의 행·열 간격을 확대하고 연결 설명은 선 위에서 축약 표시하며 선택한 연결은 전체 문구 표시

## 2026-07-13 유저플로우 집중 보기

- 전체 흐름에서 노드를 선택하면 이전·다음 2단계와 해당 레인만 확대하는 집중 보기 추가
- 전체 보기 복귀, 현재 표시 단계 수, 집중 상태를 명시하고 연결선을 직각 경로로 변경
- 집중 보기에서는 전체 레인 크기가 아니라 표시 노드에 맞춰 viewport를 계산해 긴 프로젝트의 글자 겹침을 완화

## 2026-07-13 시스템 설계 연결선·문구 겹침 수정

- 직선 연결을 여유 있는 직각 경로로 변경해 같은 열의 노드 본문을 연결선이 가로지르지 않도록 수정
- edge 라벨에 불투명한 테마 배경과 안쪽 여백을 적용하고 세로 노드 간격을 확대

## 2026-07-13 시스템 설계 캔버스 표시 회귀 수정

- React Flow 내부 renderer·pane을 덮던 불투명 테마 배경을 제거해 시스템 노드, 연결선과 배경 격자가 다시 표시되도록 수정
- 캔버스 외곽만 테마 배경을 사용하도록 selector 경계를 회귀 테스트로 고정

## 2026-07-13 시스템 설계 인텔리전스 MVP

- C4 parent 계층, 런타임 정상·실패·복구 시나리오, 품질 속성·제약과 ADR 편집 추가
- 리비전 구조 비교, 요구사항 연결 후보 승인, 연결성·추적성·복원력 점수와 안티패턴 검토 추가
- 제한된 import/use 근거 수집과 노드별 구현·커밋·배포 상태 추적 추가
- PlantUML, Structurizr DSL, runtime sequence Mermaid와 ADR Markdown 내보내기 추가

## 2026-07-13 C4·런타임·구현 drift 확장

- 하나의 시스템 모델에서 Context, Container, Component, Code 수준을 점진적으로 탐색하는 C4 drill-down을 추가했다.
- 런타임 연결 순서와 비동기 흐름을 시각적으로 구분하고 노드에서 C4 수준을 편집할 수 있다.
- 연결된 로컬 Git 저장소 안에서 코드·테스트 상대 경로와 제한된 glob을 읽기 전용으로 검사해 구현 일치·경로 누락·연결 없음 상태를 표시한다.

## 2026-07-13 관점·패턴 기반 시스템 설계 정렬

- 단일 JSON 모델에 `viewType`(구조·런타임·배포·개발)과 `architecturePattern`(자동·계층·허브·파이프라인·이벤트·배포)을 추가했다.
- 자동 감지는 노드 유형과 연결 구조를 분석하고, 선택한 패턴은 캔버스 좌표만 다시 계산한다. 사용자가 저장하기 전에는 기존 불변 리비전을 변경하지 않는다.
- 기존 리비전은 구조 뷰·자동 정렬 기본값으로 호환하며 Codex 제안은 설계 동인·품질 속성·제약·트레이드오프를 검토하도록 생성 지침을 강화했다.

## 2026-07-13 시스템 설계 캔버스

- 기능명세·유저플로우·수동 와이어프레임 ID, 코드·테스트 경로 연결
- Markdown·JSON·Mermaid·PDF 요약 및 `.projectstudio` 동기화 추가
- 상세 설계와 제한 사항은 `docs/system-design.md`에 기록
- 그룹 경계 안의 일반 노드를 그룹과 같은 거리만큼 함께 이동
- 생성 와이어프레임 SQLite 영속 저장·재조회와 시스템 설계 체크박스 연결

# 2026-07-14 데이터 프로젝트 검토·스윔레인 정합성

- 저장된 분석 단계의 레인 ID가 현재 프로젝트 유형 템플릿과 달라도 세로 순서를 기준으로 안전하게 대응시켜, 비어 보이는 스윔레인이 생기지 않도록 했다.
- 처음 여는 프로젝트에 이미 저장된 사용자 분석 흐름이 있으면 레이아웃 버전 정보가 없다는 이유만으로 자동 교체하지 않는다.
- 데이터·ML 시스템 노드는 웹 기능명세 대신 데이터셋, 실행 작업 또는 분석 단계 중 하나와 연결됐는지 검토한다.
- 실행 작업의 코드·테스트 경로는 계획 단계가 아니라 구현을 시작한 시점부터 필수 추적 대상으로 검사한다.
- 기본 생성 단계 일부만 남은 손상된 실행 파이프라인은 표시 문구가 아니라 안정 노드 ID로 사용자 정의 단계와 구분해 감지하고, 누락된 레인·노드·연결을 기본 템플릿으로 복구한다.
- 실행 파이프라인 노드·연결 ID에 프로젝트 ID를 포함해 여러 데이터·ML 프로젝트가 동일한 기본 ID로 충돌하던 전역 SQLite 기본키 문제를 제거한다.
- 로컬 Git 저장소 연결을 전역 브라우저 설정이 아니라 프로젝트별 SQLite 필드에 검증·저장하고, 구현 일치 검사에서 현재 프로젝트 연결을 다시 조회한다.
- 시스템 설계 헤더는 좁은 창에서 도구 모음을 별도 행으로 배치하고 한글 제목의 글자 단위 줄바꿈을 막는다.
- 전체 작업 화면의 버튼·제목·레이블·설명 문구에 한글 단어 단위 줄바꿈 규칙을 공통 적용하고, 코드·경로만 긴 문자열 분리를 허용한다.
- 데이터 설계의 실행 작업 생성 버튼은 내용 너비를 유지하는 소형 액션으로 조정해 좁은 패널에서도 `생/성`처럼 음절이 갈라지지 않게 했다.

- 완료 상태는 기존 `metadata_json`에 저장해 SQLite 스키마 변경 없이 이전 프로젝트와 호환한다.
- 화면 상단에 전체 완료 수·백분율, 대주제 시트마다 완료 수를 표시한다.
- 저장이 실패하면 화면만 완료된 것처럼 남기지 않고 기존 상태와 오류 안내를 유지한다.

# 2026-08-21 유저플로우 삭제 상태 보존

- 자동 생성된 유저플로우 노드를 삭제한 뒤 화면을 다시 열면 같은 ID가 재삽입되던 문제를 수정했다.
- 삭제 노드 ID는 프로젝트별 tombstone으로 보존하고 초기화·기본 정렬 시 해당 노드와 연결선을 건너뛴다.
- 사용자가 같은 ID의 노드를 명시적으로 다시 만들면 tombstone을 제거해 복구 가능성을 유지한다.

# 2026-09-03 기능명세 대주제 시트 뷰포트 복구

- `전체 기능`에서 대주제 시트로 전환할 때 React Flow가 이전 전체 뷰포트를 유지해 해당 가지가 화면 밖에 숨던 문제를 수정했다.
- 대주제별 필터링은 그대로 유지하고, Tree View의 대주제 전환 시 현재 가지를 기준으로 캔버스를 다시 맞춘다.
- 로컬 공개 데모에서 인증 대주제 39개, 지구본 대주제 19개 노드가 모두 화면 안에 표시되고 전체 151개 기능으로 정상 복귀하는 것을 확인했다.

# 2026-09-03 유저플로우 자동 정렬·기능명세 노드 비율 개선

- 유저플로우 자동 정렬이 생성 기본값과 ID가 같은 노드만 이동하던 제약을 제거하고, 현재 저장된 노드와 연결선을 기준으로 모든 열·분기 행을 다시 계산하도록 변경했다.
- 사용자 정의 노드와 공개 데모 노드도 기본 정렬 320px, 좁은 정렬 250px의 열 간격을 보장하며 새 하위 노드는 기본 간격으로 추가한다.
- 기능명세 노드를 320×42px의 가로형 카드로 조정하고 제목·상태 정보를 한 행에 배치했다. 트리 열 간격과 행 간격도 새 카드 비율에 맞췄다.
- 로컬 공개 데모에서 전체 유저플로우 110개와 기능명세 151개 노드의 화면 겹침이 각각 0개인지 확인했다.
